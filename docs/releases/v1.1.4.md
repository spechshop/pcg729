# pcg729 v1.1.4

PHP 8.5.10 CLI ZTS para Linux x86_64, com linkagem estática, Swoole
6.3.0-rc1 (`6.3.0RC1`) e psampler 0.6.1. Esta versão distribui exatamente o
executável existente em `buildroot/bin/php`, sem recompilação, strip ou
alteração do original. A tag inclui os patches Swoole revisão 3, ABI v1,
e fixa a origem da psampler usada pelo build.

## Assets e integridade

- `pcg729-linux-x86_64-zts`: executável completo, 137.769.360 bytes.
- `SHA256SUMS`: checksum do executável, no padrão das releases anteriores.

SHA-256 do executável:

```text
09d08e11460a10721544a8a3e90a0d856ec7614ae877183527da3c88f81b10df
```

Após baixar os dois assets:

```bash
sha256sum -c SHA256SUMS

./pcg729-linux-x86_64-zts -v
```

## Novidades

- `Swoole\Buffer` com armazenamento nativo reutilizável.
- `Swoole\Coroutine\Socket::recvfromInto()` para receber UDP diretamente no
  buffer, sem criar uma `zend_string` intermediária para o payload.
- API C versionada de leitura nativa do Swoole, ABI v1.
- API binária v1 da psampler e `ByteBuffer::appendBuffer()`, incluindo slices
  e conteúdo binário com NUL.
- Integração nativa Swoole/psampler dentro da própria extensão psampler,
  habilitada neste build, sem extensão de ponte separada.
- Correções de lifecycle, ownership e cleanup em caminhos de `zend_bailout()`,
  incluindo liberação de guards e pins de `recvfromInto()` e do empréstimo
  durante falha de alocação em `appendBuffer()`.

`appendBuffer()` copia para o armazenamento próprio do destino. A vantagem
arquitetural é eliminar a string intermediária do payload. Os benchmarks
informados para os caminhos tradicional e nativo mostraram desempenho
praticamente equivalente; não se anuncia ganho de CPU ou throughput.

## Validação deste executável

- PHP 8.5.10 ZTS, ELF64 Linux x86_64 estático, arquivo completo e executável;
  igualdade com `source/php-src/sapi/cli/php`.
- `ByteBuffer::supportsNativeBuffer(new Swoole\Buffer(2048))` e
  `method_exists(new ByteBuffer(4096), 'appendBuffer')`: ambos `true`.
- `php --ri psampler`: API binária v1 e ponte Swoole habilitada com read ABI v1;
  símbolos públicos C presentes no ELF.
- UDP com 0, 1, 12, 160, 1024 e 2048 bytes, integridade binária, overflow,
  10.000 reutilizações, scheduler, timeout, cancelamento e recepção posterior.
- Rejeição de leitura concorrente e bailout no destrutor do peer, em processos
  isolados com saída fatal 255 esperada; guard liberado no shutdown.
- Suíte PHPT: **23 aprovados, zero falhas e 31 skips**. Inclui regressões de
  ByteBuffer/PCM, integração UDP, slices, ring, lifetime e bailout por OOM com
  integridade do destino e reutilização do buffer no shutdown.
- Os skips exigem fixtures nativas de teste ou variantes sem Swoole/sem ABI;
  essas fixtures não fazem parte da distribuição. Não contam como aprovados.

A suíte da revisão de build da psampler tinha dois testes com premissas
incorretas: reconstruir um `Swoole\Buffer` já construído e exigir destruição
enquanto a exceção ainda guardava o objeto no trace. Ambos falharam na rodada
inicial. Foram usados os dois PHPTs corrigidos, já publicados na revisão
`00bf876e92032ca33fa23c7e59f0b36b950e61d5`, e a suíte completa passou. Não houve
alteração dos fontes de produção, do executável ou do repositório externo.

## Evidências instrumentadas e limites

Os testes anteriores de ABI, guards, lifetime, bailout e integração com o
adaptador de contrato estão documentados no
[relatório de lifecycle](../../validation/native_buffers/lifecycle/REPORT.md).
Seu Valgrind/Memcheck instrumentado cobriu 31 processos: 17 sem erros, nenhum
acesso inválido ou double free, e perdas reais nos demais cenários fatais/ZTS.
Essas perdas de teardown/globals e as ressalvas históricas de PCM continuam
registradas; não se declara o ambiente inteiro livre de leaks.

Esses resultados vieram de executáveis de diagnóstico com fixtures e runtime
musl dinâmico, anteriores à ponte integrada atual. Não são uma nova execução
de Valgrind do asset estático desta release. O bailout OOM da ponte integrada
foi revalidado diretamente no executável distribuído. O relatório antigo
descreve a ponte como pendente porque registra uma etapa anterior do trabalho.
